# UCK 6.19 — v16 BREAKTHROUGH: boots to full userspace

**2026-10-07 ~08:15–08:21 UTC (03:15–03:21 CDT)** — first 6.19 boot to reach
`switch_root` + systemd userspace.

## The fix that cleared the hang (v16)

Ubiquiti's initramfs `/scripts/ubnt-init/boot-aarch64` detects the board like this:

```sh
HWID=unknown
HARDWARE=$(sed -n '/^Hardware/p' /proc/cpuinfo)
case "${HARDWARE}" in
    *APQ8053) HWID=apq8053 ;;
esac
. /scripts/ubnt-init/${HWID}/boot-${BOOTMODE}
```

**Mainline arm64 removed the `Hardware:` line from `/proc/cpuinfo` entirely** (verified in
`arch/arm64/kernel/cpuinfo.c` — no such printf). So `HARDWARE` was empty → `HWID=unknown` →
it sourced the non-existent `/scripts/ubnt-init/unknown/boot-emmc` → the boot died **before
`mountroot()` ever ran**. That was the "box is dark" root cause (on top of the console bug).

**Fix:** if the cpuinfo `Hardware:` line is empty, fall back to the device-tree model string
(`/sys/firmware/devicetree/base/model` = "…APQ8053 CloudKey Plus…"). Both paths are tried so
it stays correct on the vendor kernel too.

## Remaining blocker (now the ONLY one)

`/sys/class/net` = **`lo` only**. No `eth0`.
`usb devices` = `1-0:1.0  1-1  2-0:1.0  usb1  usb2` — **no `usb 2-1` (the SuperSpeed hub)**.
The AX88179 NIC + SATA bridge live on the SS hub → no SS PHY → no NIC.

DWC3/USB dmesg shows only HS enumeration + repeated power-cycle of the HS hub port;
the SS side never enumerates.

## Two healers

1. **systemd** `/usr/local/sbin/uck-bootcheck.sh` — PROVEN to run in 6.19 userspace.
   Bug found: `[ -b "$STOCK" ]` tested a **regular file** (always false) → restore never
   ran → boot loop. **Fixed 2026-10-07:** `-f` test + sha256 verify of the restored p42 +
   reboot only on verified success (no loop).
2. **initramfs watchdog** (v17, in `/scripts/ubnt`) — second layer if userspace never comes
   up. Staged as `uck-6.19-boot-v17.img` on the build HTTP server.

## Method notes (why this took so long, and the fix)

- v2–v11 were blind loops: no console, no dmesg, guesses. **Never again.**
- v12's SD-card capture broke the loop. **Rule: never flash a boot image without a
  capture path that survives the hang.**
- Do NOT touch `/init` (v13 regression proved it). Instrument the *vendor* scripts
  (`/scripts/ubnt`, `boot-aarch64`) instead.
- Console is UART (`ttyHSL0`/`ttyMSM0` at MMIO 0x78af000), **not USB** — there is no
  USB device-mode port on the UCK (USB-C is power-only, USB-A is host-only, no OTG).
  The SD-card tee is the practical "serial console".
