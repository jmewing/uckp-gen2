# 6.19 UCK boot — FIRST full dmesg capture (v12, 2026-10-07)

Captured by the patched initramfs (`/k11/6.19-trace.txt` on the SD card) during a real
6.19 boot. This is the first time the kernel's actual output was observable.

## Command line
`console=ttyMSM0,115200n8 net.ifnames=0 quiet`   ← console fix (was ttyHSL0)

## Key results

1. **Console fix WORKS.**
   ```
   msm_serial 78af000.serial: msm_serial: detected port #0
   78af000.serial: ttyMSM0 at MMIO 0x78af000 (irq = 29, base_baud = 460799) is a MSM
   msm_serial: console setup on port #0
   printk: legacy console [ttyMSM0] enabled
   ```
   `/dev/ttyHSM0` exists; `/dev/ttyHSL0` does not. Confirms the diagnosis.

2. **The kernel boots and the initramfs runs.** Reach `Run /init as init process`,
   mounts `mmcblk1p1` (SD), sees eMMC p1..p47, etc.

3. **USB: the xHCI host claims SuperSpeed but NO SuperSpeed device enumerates.**
   ```
   xhci-hcd xhci-hcd.1.auto: Host supports USB 3.0 SuperSpeed
   hub 1-0:1.0: USB hub found / 1 port detected     (bus1 = USB2/HS root)
   hub 2-0:1.0: USB hub found / 1 port detected     (bus2 = USB3/SS root — EMPTY)
   usb 1-1: new high-speed USB device number 2 using xhci-hcd
   hub 1-1:1.0: USB hub found / 6 ports detected    (HS side hub)
   ```
   On the vendor kernel the AX88179 NIC + SATA bridge sit on the **SuperSpeed** hub
   (`usb 2-1` → `2-1.1` = NIC, `2-1.2` = SATA). Here no `usb 2-1` ever appears →
   no NIC → no `eth0`. This is the missing **QMP USB3 SuperSpeed PHY**.

4. **The boot stalls inside the vendor `mountroot()`.** Trace markers:
   ```
   TRACE [sd-mounted]         uptime=3.41
   TRACE [after-init-top]     uptime=9.43
   TRACE [after-load-modules] uptime=10.05
   TRACE [after-init-premount] uptime=10.25   ← LAST WRITE
   (after-mountroot / after-mount-cleanup / after-init-bottom / pre-run-init-done: NEVER WRITTEN)
   ```
   So control passed into the vendor `mountroot()` (Ubiquiti rootfs/overlay assembly)
   and never came back. The systemd `uck-bootcheck.service` never ran (no
   `/mnt/6.19-bootcheck.log`), consistent with never reaching `multi-user.target`.

5. **DTS warning: reserved-memory overlaps** (`ramoops@92000000` vs `mba@92000000`;
   `cont-splash@90001000` vs `venus@91400000`). Non-fatal (pstore still registered).

## Conclusions

- **Console**: fixed (keep `console=ttyMSM0,115200n8`).
- **Network**: blocked on the missing **USB3 SuperSpeed (QMP) PHY** — must be ported.
- **Boot completion**: blocked in the vendor `mountroot()` — needs either a fix or a
  self-healing initramfs so a failed boot returns to stock automatically.
- **Reserved-memory overlaps**: cosmetic; optionally fix.
